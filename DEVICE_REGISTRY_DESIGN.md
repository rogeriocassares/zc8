# Device Registry Schema Design

## Recommended Approach: Single `device_registry` Table

**Rationale:** Use `device_registry` as the single source of truth (not separate `devices` + `device_registry`)

### Schema Design

```sql
CREATE TABLE device_registry (
    -- Identity
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),  -- UUIDv7 (via extension)
    device_key VARCHAR(64) UNIQUE NOT NULL,          -- Generated by Elysia via function

    -- Classification
    device_model_id BIGINT NOT NULL REFERENCES device_models(id) ON DELETE RESTRICT,

    -- Identifier Logic (Conditional on device_type)
    -- View will join to determine device_type, then decide which field is relevant
    eui VARCHAR(16),                                 -- EUI-64 for LoRaWAN (8 bytes = 16 hex chars)
    mac_address VARCHAR(17),                         -- MAC address for non-LoRaWAN (6 bytes = 17 chars with colons)

    -- User Assignment
    created_by UUID NOT NULL REFERENCES users(id) ON DELETE RESTRICT,

    -- Organization & Team Hierarchy
    organization_id BIGINT NOT NULL REFERENCES organizations(id) ON DELETE CASCADE,
    team_id BIGINT NOT NULL REFERENCES teams(id) ON DELETE CASCADE,

    -- Visibility & Activity
    is_public BOOLEAN DEFAULT FALSE,                 -- If public, accessible outside org
    is_active BOOLEAN DEFAULT TRUE,                  -- Soft delete
    is_global BOOLEAN DEFAULT FALSE,                 -- Available to all teams in org?

    -- Timestamps
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,

    -- Current Provider Configuration
    lns_provider_id BIGINT REFERENCES device_providers(id) ON DELETE SET NULL,  -- Only if LoRaWAN

    -- Metadata
    metadata JSONB,                                  -- For device-specific config
    last_heartbeat TIMESTAMP,
    connection_status VARCHAR(50) DEFAULT 'disconnected',

    -- Constraints
    CONSTRAINT valid_identifier CHECK (
        (SELECT dt.name FROM device_model_routing_rules dmrr
         JOIN device_types dt ON dmrr.device_model_id = (SELECT device_type_id FROM device_models WHERE id = device_model_id)
         LIMIT 1) = 'LoRaWAN' AND eui IS NOT NULL OR
        (SELECT dt.name FROM device_model_routing_rules dmrr
         JOIN device_types dt ON dmrr.device_model_id = (SELECT device_type_id FROM device_models WHERE id = device_model_id)
         LIMIT 1) != 'LoRaWAN' AND mac_address IS NOT NULL
    )
);
```

## How to Determine LoRaWAN Protocol

### Option 1: View-Based (RECOMMENDED)

```sql
CREATE VIEW device_with_type AS
SELECT
    dr.*,
    dt.name as device_type,
    CASE WHEN dt.name = 'LoRaWAN' THEN 'eui' ELSE 'mac_address' END as identifier_field
FROM device_registry dr
JOIN device_models dm ON dr.device_model_id = dm.id
JOIN device_types dt ON dm.device_type_id = dt.id;
```

**Usage in queries:**

```sql
SELECT * FROM device_with_type WHERE device_type = 'LoRaWAN';
SELECT * FROM device_with_type WHERE identifier_field = 'mac_address';
```

### Option 2: Computed Column (PostgreSQL 12+)

```sql
ALTER TABLE device_registry ADD COLUMN device_type_name TEXT
GENERATED ALWAYS AS (
    SELECT dt.name FROM device_models dm
    JOIN device_types dt ON dm.device_type_id = dt.id
    WHERE dm.id = device_model_id
) STORED;
```

### Option 3: Trigger-Based (Most Flexible)

```sql
CREATE FUNCTION determine_device_identifier() RETURNS TRIGGER AS $$
BEGIN
    -- Get device type from related device_model
    SELECT dt.name INTO NEW.device_type_name
    FROM device_models dm
    JOIN device_types dt ON dm.device_type_id = dt.id
    WHERE dm.id = NEW.device_model_id;

    -- Validate identifier
    IF NEW.device_type_name = 'LoRaWAN' THEN
        IF NEW.eui IS NULL THEN
            RAISE EXCEPTION 'LoRaWAN devices must have EUI';
        END IF;
        NEW.mac_address := NULL;  -- Clear MAC for LoRaWAN
    ELSE
        IF NEW.mac_address IS NULL THEN
            RAISE EXCEPTION 'Non-LoRaWAN devices must have MAC address';
        END IF;
        NEW.eui := NULL;  -- Clear EUI for non-LoRaWAN
    END IF;

    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER device_registry_identifier_check
BEFORE INSERT OR UPDATE ON device_registry
FOR EACH ROW EXECUTE FUNCTION determine_device_identifier();
```

**RECOMMENDATION: Use Option 1 (View) + Option 3 (Trigger) together**

- View for querying device type information
- Trigger for automatic validation and cleanup

## Team-Level vs Organization-Level Providers

### Current: Organization-Level

```
organizations_device_providers
  organization_id → device_provider_id
```

### Proposed: Team-Level (BETTER)

```sql
CREATE TABLE team_device_providers (
    id BIGSERIAL PRIMARY KEY,
    team_id BIGINT NOT NULL REFERENCES teams(id) ON DELETE CASCADE,
    device_provider_id BIGINT NOT NULL REFERENCES device_providers(id) ON DELETE RESTRICT,
    transport_endpoint_id BIGINT NOT NULL REFERENCES transport_endpoints(id) ON DELETE RESTRICT,
    is_primary BOOLEAN DEFAULT FALSE,
    priority INT DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(team_id, device_provider_id)
);
```

**Advantages:**
✅ Different teams within same org can use different LNS providers  
✅ HTTP client/MQTT subscriber can configure per-team endpoints  
✅ Better isolation and flexibility  
✅ Supports multi-provider failover per team  
✅ Cleaner permission model (users access team providers)

**Would also keep:**

```sql
organization_device_providers  -- Org-level defaults/fallback
team_device_providers          -- Team-level overrides
```

### Provider Selection Logic

```sql
-- For a device, find the provider to use
SELECT COALESCE(
    (SELECT tp.device_provider_id
     FROM team_device_providers tp
     WHERE tp.team_id = $device_team_id
     AND tp.is_primary = true
     LIMIT 1),
    (SELECT odp.device_provider_id
     FROM organization_device_providers odp
     WHERE odp.organization_id = $org_id
     AND odp.is_primary = true
     LIMIT 1)
) as selected_provider;
```

## Elysia Device Key Generation Function

```typescript
// In Elysia API route
import crypto from "crypto";

function generateDeviceKey(): string {
  // Cryptographically secure random key
  // Format: DV-{timestamp}-{randomid}
  const timestamp = Date.now().toString(36);
  const random = crypto.randomBytes(12).toString("hex");
  return `DV-${timestamp}-${random}`.toUpperCase();
}

// Route handler
app.post("/devices/create", async ({ body }) => {
  const deviceKey = generateDeviceKey();

  // Insert into device_registry
  const result = await db.query(
    `INSERT INTO device_registry 
         (device_key, device_model_id, eui, mac_address, created_by, 
          organization_id, team_id, lns_provider_id)
         VALUES ($1, $2, $3, $4, $5, $6, $7, $8)
         RETURNING *`,
    [
      deviceKey,
      body.device_model_id,
      body.device_type === "LoRaWAN" ? body.eui : null,
      body.device_type !== "LoRaWAN" ? body.mac_address : null,
      user.id,
      org_id,
      team_id,
      body.lns_provider_id || null,
    ],
  );

  return { success: true, device: result };
});
```

## Summary of Design

| Aspect             | Decision            | Rationale                         |
| ------------------ | ------------------- | --------------------------------- |
| Table Choice       | `device_registry`   | Single source of truth            |
| ID Type            | UUID v7             | Better performance than BigSerial |
| Protocol Detection | View + Trigger      | Automatic, validated, queryable   |
| Provider Level     | Team-based          | Better flexibility, isolation     |
| Key Generation     | Elysia function     | Cryptographically secure          |
| Identifier         | Conditional EUI/MAC | Enforced by trigger               |

This design supports:

- ✅ Multi-tenant with org → team → device hierarchy
- ✅ Flexible provider selection per team
- ✅ Automatic protocol-based identifier validation
- ✅ Cryptographic device keys
- ✅ Team-level HTTP/MQTT endpoint selection
- ✅ Audit trail (created_by, timestamps)
